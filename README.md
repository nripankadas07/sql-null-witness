# sql-null-witness

Parse a strict SQL predicate subset and explain TRUE/FALSE/UNKNOWN results and retained row indexes with an AST and postorder trace.

For analysts debugging why nullable rows disappear from a WHERE clause.

## Quickstart

Linux/Python3.10+; public source installation, no external service or runtime dependencies.

```sh
git clone https://github.com/nripankadas07/sql-null-witness.git
cd sql-null-witness
python -m venv .venv
. .venv/bin/activate
python -m pip install .
sql-null-witness example.json
```

The command prints deterministic JSON. Invented example retains only row2; the other two rows are UNKNOWN.

All input examples are invented. The tool reads one UTF-8 JSON file, at most1MiB, rejects duplicate keys/nonfinite numbers/unknown fields and never modifies the input. Exit0 means a completed nonfinding result; exit1 means a documented finding (infeasible deadline, unexpected deadlock, no route or failed inclusion). SQL reports all row outcomes with exit0. Exit2 means malformed/unsupported input with stderr and no partial report. Petri exit3 means incomplete exploration with no deadlock found; a found deadlock uses exit1 even if exploration is incomplete.

## Input and interpretation

Start with the exact structure in [example.json](example.json). [Expected JSON](example-output.json) is generated by the validated example.

Only one predicate: integer/text/NULL values, = <> != < <= > >=, IS [NOT] NULL, nonempty literal [NOT] IN lists, NOT/AND/OR and predicate parentheses. TRUE/FALSE/NULL may stand alone. No SELECT, joins, functions, arithmetic, quoted names, floating point, coercion, collation or database access. Column names match JSON keys exactly and are case sensitive. Comparisons require the same nonboolean integer/text type unless NULL. No short-circuit evaluation guarantee; every trace node is evaluated. Empty IN lists reject. Up to256 tokens/4096 predicate characters,1000 rows,100 keys per row; integers within ±10^15.

Identifiers are nonempty strings up to80 characters. Integer bounds exclude booleans. Required keys and types are validated. These are model diagnostics, not automatic changes to a live system. The report describes supplied data only.

## Why this small tool

A NOT IN list containing NULL can produce UNKNOWN, whose rows WHERE discards; a true/false-only mental model hides the cause.

Existing sqlite-plan-witness inspects plans, sqlite-fixture-closure extracts parent rows, sqlite-rehearsal rehearses SQL, and json tools compare structure. This explains nullable predicate semantics without connecting to or running a user database.
